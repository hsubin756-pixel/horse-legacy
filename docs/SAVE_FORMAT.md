# 저장 형식 1

앱 버전 0.2.0의 영구 저장 형식이다. 현재 모델은 `SaveCodec`, 검증은 `SaveSchema`, 파일 작업은 `SaveManager`가 담당한다. 화면은 파일에 직접 접근하지 않고 `GameSession`에 명령을 전달한다.

## 저장되는 상태

| 항목 | 내용 |
| --- | --- |
| schema_version / simulation_version | 현재 둘 다 1. 미지원 버전은 거부한다. |
| current_week / next_id | 목장 창립 이후 주차와 다음 영구 ID 카운터 |
| rng_seed / rng_state | 부호 있는 64비트 정수를 손실 없이 담은 십진 문자열 |
| selected_horse_id | 현재 선택한 보유 말 |
| farm | ID, 이름, 보유 말 ID 순서, 자금, 명성 |
| horses | 소유 여부와 관계없이 남아 있는 모든 말·조상 기록 |

Horse의 ID·이름·성별·생년·양쪽 부모·생산 목장·소유 목장·생애/경력 상태·성장 타입·6개 능력/잠재력·컨디션·부상 회복 주수·전적 필드를 보존한다. 나이는 저장된 주차에서 다시 계산한다. JSON 필드명은 GDScript 모델과 같은 snake_case를 사용한다.

필드 누락이나 알 수 없는 필드는 기본값으로 조용히 대체하지 않고 거부한다. JSON 숫자는 정수 여부와 안전한 범위를 검증한 뒤 타입을 복원한다. `true`, 숫자 문자열, 잘못된 소수, 무한값, 손실된 RNG 값은 허용하지 않는다.

소유 말 목록은 실제 말 기록과 일치해야 한다. 부모 ID는 존재하고 성별이 맞아야 하며 부모의 생년은 자식보다 앞서야 한다. 이 엄격한 시간 순서로 자기 참조와 혈통 순환도 거부한다. 부모를 알 수 없는 창시마는 빈 문자열을 사용하고, 조상은 보유 말 목록에서 빠져도 기록에 남을 수 있다.

현재 형식에는 경주 결과·임신·시설·AI 목장이 없다. 따라서 전적은 0이고 경주 결과 ID는 빈 목록이어야 한다. 해당 시스템 추가 시 모델·형식을 함께 확장한다. 기존 스키마에서 결과 ID만 받아들여 끊어진 참조를 저장하지 않는다.

## 저장 트랜잭션

1. 메모리 상태를 명시적인 DTO로 변환하고 검증한다.
2. `.tmp`에 쓰고 flush/close한 뒤 내용 일치와 스키마를 재검증한다.
3. 기존 primary가 있으면 먼저 유효성을 확인한다. 손상/미지원 primary는 일반 저장으로 덮어쓰지 않는다.
4. 기존 유효본을 `.bak.tmp`에 쓰고 검증한 뒤 `.bak`으로 교체한다.
5. 검증된 `.tmp`를 primary로 교체한다.

교체는 같은 디렉터리의 rename을 사용하고 실패 시 목적 파일을 삭제하지 않는다. 중간에 남은 `.tmp`는 로드 대상이 아니다. 마지막 교체가 실패해도 기존 primary와 유효한 백업을 유지한다.

로드는 별도의 GameState를 완성한 뒤에만 활성 상태·선택을 교체한다. 명시적인 백업 복구는 백업을 검증하고, 기존 primary가 있으면 원래 바이트를 `.before-recovery`에 보존·해시 비교한 뒤 primary를 교체한다. 빈 파일이나 잘못된 문자 인코딩의 원본도 보존할 수 있다. `.before-recovery`는 가장 최근 복구 직전의 원본 한 개를 보관한다.

## 호환성과 검증 범위

- 첫 저장 형식이므로 현재는 v1만 읽는다. 미래 버전을 자동으로 낮추거나 덮어쓰지 않는다.
- `tests/fixtures/save_v1.json`은 호환성 기준이다. 이후 버전에서는 이 파일을 새 버전으로 바꾸지 말고 마이그레이션 검사에 재사용한다.
- 파일 16 MiB, 말 10,000개, 단일 플레이어 목장과 하나의 저장 작성 프로세스를 대상으로 한다. 다중 프로세스의 동일 슬롯 동시 쓰기는 지원하지 않는다.
- Linux에서 부분 쓰기·백업 쓰기·백업 교체·최종 교체·복구 교체 실패를 주입해 기존 유효본 보존을 검증했다.
- 별도 writer가 종료된 뒤 reader가 모든 상태와 다음 난수들을 복원하고 다시 저장·로드하는 검사를 실행한다.
- 전원 장애 시 저장 장치의 내구성, 다른 OS의 파일 교체 동작까지 검증했다는 의미는 아니다.
